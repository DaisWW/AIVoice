# 代码审查清单

触发：CR、找 Bug、质量或精简。适用 Voice Lab 自有源码；`tools/` 第三方模型默认不审查。

## 原则

- 从入口追到权限、状态变化、外部副作用和清理；Findings-first，只报告有触发条件、证据和影响的问题。
- 仅审查时停在建议；要求修改时做最小修复，并复查调用点、测试和完整 diff。
- 不报告纯风格偏好；无法确认时说明需要的 GPU、Docker 或运行时验证。

## 精简与边界

- 只处理有证据的重复、死代码、职责混杂、隐藏副作用和不必要耦合，不以减少行数为目标。
- 保持高内聚、低耦合和单一主要职责；复杂度影响测试、修改或定位时才拆分函数/文件。
- 路由只处理认证、输入和 HTTP；业务走服务/领域层，数据访问走现有 persistence 模式。
- 不为单次使用增加全局状态或抽象；API 最小，不隐藏写副作用。
- 删除参数、重命名或收窄 API 前检查全部调用点；不用静态/全局状态掩盖参数问题。
- 一次精简只做一个主题；命名和错误沿用模块风格，注释只解释原因和限制。

## 正确性与安全

- 项目、声音、台本、任务、候选和下载验证项目归属；错误不泄露路径、密码或 Key。
- 上传校验大小/类型/格式，路径限制在受控根目录；async 路由不执行阻塞推理、文件 IO 或同步网络。
- SQLite 写入的事务、回滚、约束和锁明确；状态转换、恢复、取消、导出及迁移幂等。
- 文件和数据库保持一致，失败不留孤立文件或无效记录；不误删历史 SQLite、音频或配置。

## 队列与模型

- 所有推理经单个 JobQueue；检查 start/stop、锁顺序、恢复、异常持久化和 shutdown。
- 不增加 Uvicorn/后台 worker；引擎切换、取消和异常后释放模型、文件和句柄，旧任务不覆盖新状态。
- 模型输入输出、采样率、声道、时长和格式符合契约；新 provider 走 contracts/registry。
- HTTP 有超时、失败分类和响应校验；日志不输出 Key、Authorization、原始音频或上游正文。

## 前端、性能与输出

- 检查连点、取消、轮询、离页、权限失败、长文本和多候选；JS 至少运行 `node --check`。
- 只优化有样本的热点；检查重复解码、无界读取、事件循环阻塞、队列堆积和显存未释放。
- 缺陷增加最窄回归用例，优先临时 SQLite/fake 引擎；跨层改动运行 `run_tests.ps1`。
- 按 P0/P1/P2/P3 输出问题、触发条件、影响、文件/行号、证据和处理结果；报告验证及残余风险。
